How every verb works

The tool attaches to your already-signed-in Chrome (the cencon profile, port 9224), opens one background tab you never see, and drives LinkedIn the way a person does: it goes to the exact page, finds the one control by its name, acts, and then looks for the result. It never guesses coordinates and never reads an accessibility tree; that is what failed five times before. The mechanics come from the projects that already do this for a living: a production Playwright library for Page posts and first comments, a Selenium engagement framework updated in May 2026, and the verb list of Linked API, the commercial cloud-browser service.

  1. Go to the exact page. A post permalink or a profile URL. Never a feed: a feed has fifty comment boxes, a permalink has one.
  2. Prove the target. --expect "a phrase from the post" must be on the page, or the verb refuses. A wrong URL fails loudly instead of acting on a stranger.
  3. Act on the one control. Selectors from one dated file; submit and confirm buttons pressed by keyboard so a late click can never fall through to the page behind (the lesson from the Discard-over-Photo dialog).
  4. See the result. The comment text inside this post's comment list, under our name. The reaction button in its pressed state. The Connect button now reading "Pending". Never "no error".
  5. Leave nothing. Dialog discarded, tab closed, no native "Open" window on the desktop (checked by Win32 at the end of every run), and one line: RESULT ... or FAIL ... with exit 1.

The contract every caller reads

RESULT commented url=... comment_id=... seconds=14 RESULT reacted url=... kind=like RESULT staged verb=connect profile=... shot=... RESULT connected profile=... state=Pending FAIL post does not contain 'whiteboard'; refusing to comment exit 0 on RESULT, exit 1 on FAIL, nothing left behind either way

Three kinds of verb

read Returns JSON, changes nothing, needs no approval.

automatic Acts on content: post, comment, react. Runs on its own under the pacing caps, with the permalink-plus-phrase guard.

staged Reaches a person's inbox: connection notes, messages. Composes, verifies, screenshots, stops. --submit sends, and the skill says you asked for it in that same message.

The comment mechanic, step by step

  1. Open the permalink in the background tab. Wait for the post card that carries data-urn = this activity.
  2. Read the post text. If --expect is given and not found: FAIL, nothing typed.
  3. Guard: if a comment authored by us with the same text already exists, RESULT already-commented and stop. (Copied from the Selenium framework; it exists because retries used to double-post.)
  4. Click the card's own Comment button (scoped to the card, not the page), which opens the box. Focus the editor.
  5. Type by keystroke, one Enter per newline. Read the editor back and compare.
  6. Wait for the card's Post button to be enabled. Focus it, press Enter.
  7. Poll the card's comment list for a row authored by us containing the text. That row is the proof. Return its comment id and the tab is closed.
Two known traps go into the code as checks, not comments: on LinkedIn, Enter inside a message box sends, so messages (Phase 3) never press Enter while composing; and an unscoped "Post" button matches the Repost button of the post behind a dialog, so every button lookup is scoped to the card or dialog being acted on.

How each phase is proven

  • Every phase lands as its own pull request on thefrederiksen/cc-linkedin, with the selftest transcript in the PR body.
  • "Done" is three consecutive clean selftest runs on the live page with zero leftovers.
  • The selftest runs before every commit and whenever a verb fails in real use; when LinkedIn changes a control, the failure names the selector and the fix is one line in selectors.py.
  • The global linkedin skill is updated with every verb as it lands, so any session that touches LinkedIn finds the one working recipe.

Pacing that is built in, not remembered

  • Outbound actions wait 45-90 seconds apart, across sessions and agents, because the clock is a file, not a process.
  • Any "unusual activity" or CAPTCHA text is a FAIL and a stop for the day.
  • Reads have no caps except the 100-row search limit.
