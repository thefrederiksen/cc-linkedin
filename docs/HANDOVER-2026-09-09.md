## Facts that cost hours, all measured on the live page today

1. LinkedIn serves a post permalink in TWO renderings at random: the classic app
   (`data-urn` cards, `comments-comment-entity`, Quill `ql-editor`) and a new
   React app (hashed classes, `componentkey`, TipTap editor). `Post.load()`
   detects which; comment rows are mapped on the classic one; accessible names
   are the same in both and are used first.
2. Two Playwright clients attached to one Chrome block each other's navigations.
   Hence the lock. Never run two verbs concurrently on one port; never bypass
   the lock. The lock must be released when a browser session ends (it once
   held for a whole process and a later step in the same process waited 462 s
   on itself).
3. The video is uploaded AFTER the Post/Schedule click, from inside the page.
   Never navigate away until the upload traffic is done; a request pending for
   more than two minutes is a long-poll, not an upload.
4. The Discard prompt's button sits exactly over the admin page's Photo button;
   a late mouse click opens a native OS file chooser. Dismiss/Discard/confirm
   are pressed by keyboard. A comment's menu is an unlabelled
   `button.artdeco-dropdown__trigger`; a reply box is pre-filled with the
   author's @mention; a comment's article holds TWO buttons named "Reply".
5. The cencon Chrome wedges (renderer crashes). Another session rewrote
   `%LOCALAPPDATA%\cc-director\connections\bh-profiles.ps1` today with a health
   probe and `restart`. A run caught by a restart ends with "no Chrome on port
   9224" and nothing half-done. Do not call `up cencon` in a loop; call it once.
6. The `Pace` caps are per day per kind; the numbers are in `kit/browser.py`.
